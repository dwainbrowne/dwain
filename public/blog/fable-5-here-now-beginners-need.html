AI developer · July 3, 2026

Fable 5 fixed problems other models couldn't, and I still review what it ships.

In a July 2026 live stream I'd had about 48 hours with Claude Fable 5, Anthropic's new model, and I'd already hit 100% of my usage. It handled things I couldn't get done properly with GPT-5.5 or Claude Opus 4.6 to 4.8. I could only use that speed because I know my own code well enough to check its work.

The business case

As of July 2026 I was spending about $1,200 a month on AI. About three weeks before the stream, after a Copilot bill of about $700, I left Visual Studio and GitHub Copilot for Claude Code and Codex, full time and maxed out on both. In the 48 hours I'd had Fable, my GitHub contributions roughly doubled.

Our company is four people, and I plan to keep it that way. On any given day I get more done than my old team of six developers did in a month, maybe two. I said on stream that I think a five-person team could build a billion-dollar company.

The point of the stream was that Fable 5 won't save you from bad judgment as a vibe coder. With output that fast, the calls that still need me are where code belongs, what the model got wrong, and when to stop building and sell. My advice to beginners was to build a mental model of your code before you trust an agent with it.

What Fable 5 cracked

I'd been building an AI calling assistant into my lead app for voicemail drops and appointment follow-ups, running SignalWire and Twilio side by side. It worked as a prototype. In production it stalled for weeks while I iterated with GPT-5.5 and Opus 4.8. I told Fable how the system worked and how it should behave, and it churned for about 40 minutes. Then it said it would call my phone. The phone rang and I heard nothing. I told it so, it fixed one more problem, and that job was done.

It also built the website for LeadScore AI. I prototyped the front page in Claude Design and picked a product-style layout over a minimalist or bold one. Then I told Fable to go through my documentation, my code and my features and build the site. Beyond that I only gave it specific requirements for the marketing copy. It built about 30 pages, one per feature. Earlier models would have stopped around 10.

Over that weekend it built the outbound side of my system too, and the rules behind it came from what I've learned over the years. Start with a message built on a pain point your buyer has. If you send the same email to everyone, Google and Microsoft flag it as spam, so each email has to be personalized, which is where AI helps. My working number was about 30 to 35 emails a day, and even 50 is pushing it. Spread your sending across three or four inboxes per domain and several extra domains, and keep your main domain out of it. Fable built the part where I buy a domain and the system sets up deliverability, then routes replies from all of those domains back to one place.

Twenty years of reading code

I've been a developer for about 20 years. At one point I had 13 employees, six of them developers, and for about five years I reviewed every line of code they wrote, every day. That's how I got my application stable.

Working in Claude and Codex feels like writing a Word document, and I act more like a project manager orchestrating people, even though I'm still checking in code and telling it don't do this, change that. The shift took me about a week and a half. Visual Studio, the tool I'd used for most of my programming life, is now secondary.

The code is a monorepo I counted live on stream at about 1.5 to 1.6 million physical lines. Cursor is really good, but for .NET I use JetBrains Rider on my Mac, with Opus running in the Claude desktop app and Codex beside it. Codex starts a job and Opus fact-checks it, especially on security work. For a new feature I let Codex write it and audit itself, take the output to Opus 4.6 for another audit, and then send that back to Codex. There are always small gaps. I wrote up how I run a codebase this size in my monorepo post.

Copy code by hand first

When I started my lead app, I designed the UI in v0. This was before Lovable. v0 wrote everything in React, and I prefer Nuxt and Vue. I'd write code in v0, copy it down, edit it locally, and go back and forth. Building the app piece by piece like that means I know where each part of the code is supposed to live, so when the AI puts something in the wrong place, I can tell it where it goes.

I think that mental model is what separates junior vibe coders from seasoned developers. My advice for anyone learning now: ask ChatGPT or Claude for the code, paste it into your editor yourself and make it work. Do that for a few websites, 20 if you can. It will feel slow and painful, like a waste of time. You'll come out with a mental model that makes larger applications second nature. I go deeper on that in vibe coding with engineering judgment.

Review what ships overnight

I run a Codex skill called transcript to issues. It takes a meeting transcript and turns it into categorized GitHub issues. Every day at 3 a.m., a Codex routine takes the top issues from my ready and in-progress columns and works them. I told it to flag anything that touches the database, any major feature that spans several components, and any big overhaul. Entry-level to medium work it finishes without asking and checks in to dev, where I review and test it in the morning.

On the stream my board had 4 items in backlog, 9 ready, 14 in progress and 63 in review. I'd never had more work to review than code to write. Done is never done, though. I added another 30 or 40 issues that morning.

At some point you have to commit to selling. I'm guilty here too. There are days I've scaled back on selling my product because I wanted to keep building, and breaking off to sell is the hard part.

Keep the judgment yours

Fable 5 got me past problems I'd been stuck on for weeks. I could trust what it shipped because I knew where the code belonged, and I still review what it flags for me. If you want help setting up that kind of review loop on your own codebase, book a strategy call.
